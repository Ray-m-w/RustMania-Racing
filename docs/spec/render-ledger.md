# Rendering: differences ledger (port/crates/mr-bevy)

What the Bevy presentation does differently from the game's renderer, and why.
Simulation state is never derived from rendering (ADR-0002 split).

| Area | The game | mr-bevy | Why / status |
|---|---|---|---|
| Rasterisation | GPU, affine texture mapping, 15-bit colour, dithering | GPU via wgpu, perspective-correct, 8-bit sRGB, no dither | modern presentation; texel choice, colour modulation (texel*rgb/128) and nearest sampling match |
| Draw order | ordering tables, no depth buffer | depth buffer; layer 1 (far stand-ins) + sky drawn in a first camera pass, layer 0 + kart over it with a fresh depth buffer; layer-0 "ground" list depth-biased under the near list | reproduces the OT layering that matters on DOCK (DAT.md); exact OT order within a layer is not reproduced |
| Near-polygon subdivision (layer 0) | near polygons split 2x2 with interpolated UV/colour | not done | only affects affine warp, unnecessary with perspective-correct mapping |
| Texture LOD (slots 0..3) | UVs >> 1 / >> 2 by depth (decimated copies) | stored UVs always (LOD 0) | LOD 0 is what the game shows up close; distant ground is sharper than the original |
| Per-frame object selection | visibility stream + cull | same rule (Dat::drawn), from the game's camera | exact |
| Animated textures (RAW type 0x22) | FUN_8007A9DC -> FUN_800311AC copies one frame per strip into VRAM every race frame (frame from DAT_800B0D90; strip 0x1E from DAT_800B07D4) | same copies (animtex.rs, effects.md), cached page images rewritten in place | strip 0x1E's counter DAT_800B07D4 is approximated by the frame counter (its phase at race load is not modelled) |
| Kart/driver parts | per-part matrices from the kart record | same rules (kartmodel.rs, MDL.md) | exact for the parts; depth-cue colour factors (+0x414..) not applied |
| Lighting / fog | per-vertex colours, depth cue | per-vertex colours only | depth cue not ported |
| Resolution / aspect | 512x240, 4:3 | window size, 4:3 projection (90 x 73.7 deg) | modern; widescreen is a later choice |
| Track objects outside DAT scenery | start/finish banner: cloth from DAT chunk 9 (FUN_800351e8, animated by FUN_80035004); kart shadows (0x800C8B38 list, FUN_8002ADA8); pickups (0x800E1B70 boxes, 0x800E2370 tokens, FUN_8007E21C); particles 0x800E0C20 (FUN_80010E90), sparks 0x800B4540, projectiles 0x800DDC50, via the 0x800DF688 billboard batch (effects.md) | banner drawn with the game's geometry, animation, UVs, shading and 0x2000 cull (scene::ObjectsPlugin, DAT.md "Start/finish banner"); cloth phase for replays taken from the lap1 savestate; particles, sparks, pickups and projectiles drawn by effects.rs (below) | banner exact to the GTE vertex; the phase is power-on dependent in the game |
| Kart shadows | one FT4 per kart from the kart record (FUN_8003E91C tail, FUN_8003E59C ground matrix, FUN_8003E3A0), slot 0x14 kart-silhouette tile at kart+0x16C/0x16D, subtractive blend (ABR 2), faded from view z 0x1000 to 0x1800 (world >> 5), +-0x30000 cull (FUN_8002ADA8) | same record (kartshadow.rs, exact on 17/18 oracle records, the other 1 unit off); drawn as a black alpha-blended quad, alpha = 1 - ((0.4 - F)/0.4)^2.2 (B - F matched at a mid-tone, linear-space blend), depth-biased over the ground; interpolated like the kart | subtract approximated (darker grounds are darkened less than the game does); player kart only until Session::others exists |
| HUD | position, lap, timer, minimap, items, banners | everything of the 1-player race HUD (hud.md, primitives exact vs GP0 on 345 frames); drawn as quads / triangles / 1-pixel lines over the 3D in a 512x240 ortho view; modulation in linear space as (c/128)^2.2; abr 3 (B+F/4) as additive at 1/4, abr 2 as a 50% blend; the texel STP bit is ignored (whole primitive semi) | lines are quads one game pixel wide; special-move icons use character texture slots 9/0xA that the course RAW does not load (wrong texels until the character textures are decoded) |
| AI karts, items, effects (stars, sparks, skid marks, shadow) | drawn | AI karts drawn (Session 3); particles, sparks, pickups, projectiles drawn (effects.rs) from the oracle capture (`--replay-capture`) and, once track A exposes them, the live session; skid marks, kart status effects (FUN_80037B80), the special glow (+0x4D6), the exhaust flames FUN_8007D660 and projectile models (flag 0x400, FUN_80030AD8) not drawn | Session 4 |
| Billboards (particles, pickups, projectiles) | GTE: view-space quad of half size (w, h) world>>5 units, x stretched 1.6 (0x1999) or 1.5 when rotated for the 512-pixel screen, rotated in the screen plane, ordering-table depth (+ a per-sprite bias) | camera-facing quads in world space, square (Bevy's 4:3 projection already has the aspect), one dynamic mesh per material, depth-tested; anchor 4 (stand on the point) honoured; ground-flat particles (0x10) flat in world x/z | OT bias and the 1.5 vs 1.6 stretch of rotated sprites not reproduced |
| Blend B - F (abr 2, smoke) | subtractive | black blend with alpha = the texel's brightest channel * the fade (dst * (1 - F k)) | darker backgrounds are darkened less than the game does (as kart shadows) |
| Spark streaks | LineG2, 1 pixel, additive, black to colour | additive quads ~1 game pixel wide facing the camera | width by distance approximated |
| Frame rate | 30 Hz logic; 20 Hz in heavy scenes | 30 Hz logic always, rendering interpolated at display rate | intentional: the port never slows down (physics ledger) |
