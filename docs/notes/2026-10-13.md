Brief item 7: (a) input latency in the faithful mode, (b) a true 60 Hz logic

What was done
1. Baseline: naive dt = 1 (the existing `tick_dt(b, 1)`) measured with a new
   feel harness (mr-sim examples/feel60.rs) against the faithful 30 Hz port
   (no oracle needed): accel / jump / turn already within 1-2 %; AI item

   race with five AI karts: the solo session never completes a lap on them,
   even at 30 Hz), so "player on recorded inputs" became 1 s open-loop
   windows of a recorded 30 Hz drive from identical states, plus closed-loop
   AI-driven Kermit races for lap times and the racing line.
2. Proof tool first: examples/hz30_fingerprint.rs hashes the whole race
   state every 500 ticks of 7 long 30 Hz sessions; taken before any change,
   identical after every change.
3. `SessionConfig::logic_hz`, `RaceGlobals::hz60` (mode + pair phase), and
   the per-term treatment in kart-physics-ledger.md section 12 (random
   tries / draws once per pair, AI once per pair with dt 2 and held,
   round robin per pair, pickups collected on the pair's first tick,
   per-tick kicks rescaled, remainder carry, power-turn steer, velocity
   frame lead, load frame = first pair). `Session::snapshot` / `restore`.
4. What the harness found on the way (each a 60 Hz-only fix):
   - top speed -0.22 % (twice the truncation of the frame conversion):
     remainder carry -> 0.00 %;
   - AI-driven Kermit +2.7 % race time, 10x wall contacts: the power turn
     read the mid-pair steer (+25 % yaw per tap) -> pair-start steer; then
     +1.5 %, a DOCK hairpin costing +0.22 s per pass from identical states
     (200 entries): the game's first VBlank moves in the second VBlank's
     frame (one conversion per tick after both steering sub-steps); the
     60 Hz mode now leads the frame by this tick's yaw on the pair's first
     tick -> 4.724 vs 4.735 s, race time -0.03 % over 80 races;
   - tokens +8 %, boxes / fires +7 %: pickups tested every VBlank catch
     more -> collection on the pair's first tick (the game's sampling);
   - open-loop water windows equal (-0.2 %); the wall-top allowance at dt 1
     (96 vs 288) changed nothing measurable (left as the game's table).
   - Run counts: with 6 races per mode one of the eight item statistics fails
     2 sigma by chance in most runs (fires, hits, turbo in turn); feel60 now
     runs 100 six-kart races and 80 player races per mode (~30 s CPU, no
     oracle: the economy rule's oracle runs are untouched).
5. mr-bevy (pacing.rs, small hunks in main.rs / settings.rs): the pad is
   sampled every display frame (presses latched to the next tick); with
   `low_latency` (default on) the display interpolates from the last real
   tick toward the coming tick, which it runs on a snapshot with the buttons
   held now and throws away (27 us; re-run only when the tick or the
   buttons change). `logic_hz` = 30 | 60 selects the mode (Time<Fixed> rate,
   routes at 1 VBlank per tick, trace dt column). HUD timer / countdown read
   game time (VBlank units); effects and animated textures use the VBlank
   frame counter; sfx.rs renders `dt` VBlanks per sound frame, so 60 frames
   x 1 VBlank keep the pacing (audio-stats: no new underruns at 60 Hz).
