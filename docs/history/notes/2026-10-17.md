### Phase 15 addendum: the "stall" after LOADING (lead's question)
- Verdict: test tooling, not a game hang. Two causes, both in the menu
  script: (1) an in-process course change replaces the boot arguments
  with the course's (menus.rs `course_args` drops `--menu-keys` /
  `--menu-shots`), so after the boot the script systems found no flags and
  the run neither pressed keys nor took shots nor exited; (2) Front::vb
  restarts at 0 on every boot. Also the course's first load since power-on
  plays its movie (SWAMP: MM1_15.STR, 579 frames, ~39 s; the script clock
  stops during movies) - the game's behaviour, skippable with CROSS.
- Fix (tooling): menus.rs `SCRIPT_VB` (advances with Front::vb, never
  reset) and `script_arg` / `scripted` (the flags from the process's own
  arguments); demo.rs uses `scripted()`. No game-path change. README
  updated (`--menu-keys` VB semantics).
